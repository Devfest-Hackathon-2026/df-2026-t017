## 0. エグゼクティブサマリー

**Closet Me** は、ユーザーの手持ち服（実写写真）から、当日の**天気・時間帯寒暖差・Google Calendarの予定・本人の好み（寒暖感度）・着用履歴（死蔵度）**を統合し、毎朝の装いを共創するAIパーソナルスタイリストです。

### 解決する本質的課題
日本の家庭には「1年間一度も袖を通されない死蔵衣類」が1人あたり平均25〜30着存在します（環境省調査）。その原因は「服が足りない」からではなく、**「手持ち服 × 時間帯ごとの寒暖差 × 切り替わる予定（TPO）」の組み合わせパターンを人間が毎朝想起しきれず、無難な同じ服を繰り返すか、着回せない服を買い足してしまうこと**にあります。

### 大会テーマ「Own the Why, Build with Intent」への回答
Closet Me はAIにすべてを丸投げする単なるLLMラッパーではありません。
1. **物理的快適性は「数理モデル」で解く**: 被服気候学の国際指標 **Clo値（衣服の断熱性）** と活動代謝量（METs）から熱的に安全な組み合わせ空間を決定論的に事前フィルタリング。
2. **視覚的調和と死蔵服の再発見は「ベクトル検索」で解く**: **Vertex AI Multimodal Embeddings（1408次元）× Cloud Firestore Vector Search** で、眠っている服の新しい着回しを発掘。
3. **TPO文脈理解と納得の言語化は「Gemini」で解く**: **Vertex AI Gemini 1.5 Flash（Structured Outputs）** が多基準評価を行い、納得感のある推薦理由と推論トレースを生成。
4. **人間中心の創作共創体験（クリエイティブ）**: AIの提案を鵜呑みにせず、ユーザーが1タップで靴やアウターを差し替える（Swap）と、裏側の数理物理エンジンがリアルタイムに熱的適合性を再判定。「AIの安全柵の中で人間が直感的に装いを創り出す」体験を実現しました。

## 1. 課題定義とカテゴリー適合

### 1.1 一文で表す課題
> クローゼットに十分な服があるにもかかわらず、「天候・時間帯ごとに切り替わる予定（TPO）・手持ち服の組み合わせ」を毎朝統合して考える認知的負荷が高く、結果として毎朝の迷いと「着られない死蔵衣類」が生まれている。

### 1.2 課題の構造と解決アプローチ

| 課題の瞬間 | 現状の代替手段 | 残る問題 | Closet Me による解決 |
|---|---|---|---|
| **多拠点TPOの切り替え負荷** | 天気予報＋カレンダー＋記憶 | 情報が分断され、全時間帯・場所を満たす服装が浮かばない | Google Calendar × Weather API を統合し、時間帯別TPO・寒暖差を自動解析 |
| **着回し想起の限界（死蔵化）** | クローゼットを見返す・SNS検索 | SNSの服は自分が持っておらず、所有服の新しい組み合わせに気づけない | 手持ち服ベクトルの近傍探索により、眠っていた服を含む新鮮なコーディネートを発見 |
| **体感と物理条件のズレ** | 気温だけ見て勘で選ぶ | 移動中暑い、夕方凍える等の不快感が発生 | 被服気候学（Clo値×METs）数理モデルにより熱的快適性を物理的に保証 |
| **服登録の初期離脱** | 手作業で属性入力 | 面倒で使い始められない | 写真1枚アップロードまたは「黒ニット追加」のテキスト入力からGeminiが自動タグ付け・Clo値推定 |

### 1.3 カテゴリー適合：なぜ「クリエイティブ」なのか
本プロダクトは単なる「朝の時短便利ツール」ではありません。  
手持ちの服という**「限られた制約資産」の中から、気象と予定という生活文脈に適応した「新しいスタイルを創り出す」創作支援基盤**です。ECで買わせる消費誘導ではなく、今あるものを活かして自分らしい装いを編集・表現するクリエイティビティをAIとの対話を通して引き出します。

## 2. ターゲットユーザーと主要利用シナリオ

### 2.1 ターゲットユーザー
- **Primary Persona**: 18〜30代の学生・社会人（大学・バイト・インターン・商談・会食など1日に複数のTPOが切り替わる人）。
- Google Calendarを日常的に利用している、または利用に抵抗がない。
- スマホで朝1分以内に、納得感を持ってその日の服を決めたい人。

### 2.2 典型的な利用シナリオ
- **シナリオA（TPO多層日）**: 午前は大学・午後はオフィス出社・夜は食事会。  
  → AIは「オフィスでも違和感のない上品さ」を保ちつつ、夜の寒暖差に対応する羽織り（カーディガン等）を提案。
- **シナリオB（悪天候・寒暖差）**: 朝は晴れ18℃だが夕方から雨で11℃に急降下。  
  → 降水確率と気温変化を捉え、非撥水の靴を除外し、防寒性と防水性を備えたアウターを自動サジェスト。
- **シナリオC（新しい服の登録）**: チャットで写真を送るか「撥水のスニーカー買った」と入力。  
  → 被服気候学属性（カテゴリ・Clo値・フォーマル度）を即座に抽出し、登録完了カードを表示。翌朝の提案候補へ即座に合流。

## 3. UI/UXアーキテクチャ：ガイド付きリッチカード型チャット

従来の「静的な管理画面」から、**「毎朝の専属パーソナルスタイリストと対話する」ガイド付き会話型UI（Guided Conversational UI）**へと昇華させました。

```text
+-----------------------------------------------------------------------+

+-----------------------------------------------------------------------+
|  [AI] おはようございます！東京は最高18℃/最低11℃、午後に雨の予報です。  |
|       今日は「出社・商談」の予定がありますね。                        |
|                                                                       |
|  ┌─────────────────────────────────────────────────────────────────┐  |
|  │ 【おすすめコーデ】きれいめスマートオフィス（Clo値: 0.95 快適）   │  |
|  │  ┌──────────────┬──────────────┐                                │  |
|  │  │ [実写アウター]│ [実写トップス]│ 2×2 実写写真コラージュ        │  |
|  │  ├──────────────┼──────────────┤                                │  |
|  │  │ [実写ボトムス]│ [実写シューズ]│ （架空画像ではなく本人の服）  │  |

```

### UXの特徴
1. **2×2 実写写真コラージュ**: 生成AIの架空イラストではなく、ユーザーが実際に登録した服の写真だけを組み合わせて提示。「明日すぐ真似できる」納得感を実現。
2. **インライン・アイテム差し替え（Swap & Co-creation）**: 「靴だけ変えたい」などの要望に、裏側の物理ソルバー（CSP）が熱的安全性を崩さない代替アイテムを動的にサジェスト。
3. **推論プロセスの可視化（Own the Why Trace）**: 各提案カード内に「Stage 1 物理計算結果」「Stage 2 ベクトル類似度」「Stage 3 Gemini評価」の推論メトリクスを折りたたみ表示し、ブラックボックス化を排除。
4. **チャットからのワンタップ服登録**: カメラ撮影、画像送信、または「白スニーカー追加」などの自然言語入力で即座に服の属性を推定してプレビュー表示。

## 4. システムアーキテクチャ（Google Cloud ネイティブ）

```text
[Smartphone / Web Browser]
       │
       ▼
[Firebase App Hosting] ──────── Next.js 15 (App Router / TypeScript / Tailwind CSS)
       │  HTTPS + Firebase Auth ID Token
       ▼
[Google Cloud Run] ──────────── FastAPI (Python 3.12 / asia-northeast1)
       │
       ├── 【認証・セキュリティ】: IAM / ADC キーレス認証, Cloud Secret Manager
       ├── 【プライバシー】: Google Calendar 予定の不可逆サニタイズ（Zero Raw PII Leakage）
       ├── 【AIコスト最適化】: 3段階省コストIntentルーティング（Tier 0〜2）
       │
       ├── 【Stage 1: Physics Engine】: 被服気候学 Clo値 × METs 制約充足ソルバー (CSP)
       ├── 【Stage 2: Vector Search】  : Vertex AI Multimodal Embeddings × Firestore Vector Search
       ├── 【Stage 3: Gemini Re-ranker】: Vertex AI Gemini 1.5 Flash (Structured Outputs)
       └── 【可観測性】: Cloud Logging 構造化推論トレース出力
```

### 4.1 3段階・3軸決定論的推薦パイプライン（被服気候学 × 色彩数理 × Firestore自己適応）

1. **Stage 1: 被服気候学・寒暖差着脱ソルバー（CSP Engine）**
   - 天気予報（気温・風速・湿度）とカレンダー予定のピンポイント時間帯気温・推定代謝量（1.2〜2.6 METs）、および **Cloud Firestore から取得したユーザー固有の体感学習補正（`personal_clo_offset`）** を合成し、目標Clo値レンジを決定論的に算出。
   - 昼夜の寒暖差（$\Delta T \ge 5.0^\circ\text{C}$）を検知した場合、インナー単体とアウター着脱時のClo値を個別評価し、屋内外の寒暖差に適応できる重ね着構造（Layering Adaptability）を保証。
   - 手持ち服の全組み合わせから、物理的・熱的許容範囲に収まる組み合わせのみをフィルタリング。
2. **Stage 2: 3軸決定論的スコアリング＆死蔵衣類ブースト**
   - 審査員に説明のつかないブラックボックスや乱数ノイズを排除し、透明な3軸スコアリングを採用：
     - **熱環境・重ね着適応（40%）**: 目標Clo値との近接度＋寒暖差に対する着脱適応性ボーナス。
     - **TPO・色彩調和（35%）**: 要求フォーマル度合致度（分散ペナルティ含む）＋色相環・明度彩度に基づく色彩調和スコア。
     - **死蔵衣類復活（25%）**: 未着用日数に応じたシグモイド曲線（Sigmoid）ブースト＋手持ち服タグマッチ。
3. **Stage 3: 推薦結果の Own the Why トレース出力 ＆ 1タップ体感フィードバック**
   - 推薦理由と各軸のスコア内訳（Physics/Color/Dormancy）をUI上で完全に開示。
   - 着用後の「🥶 寒かった (+0.08 Clo)」「😊 快適 (0)」「🥵 暑かった (-0.08 Clo)」1タップフィードバックにより、**Cloud Firestore（`users/{uid}`）へ体感差分を自動蓄積・自己補正**。次回推薦精度を永続的に向上。
   - ※ 画像認識や自由対話など入口・境界には Google Gemini 1.5 Flash を活用し、Google Cloud技術とのベストプラクティスを体現。

### 4.2 3段階省コストIntentルーティング（$20 Cloud Credit 保護設計）

大会付与の `$20` クレジットを枯渇させず、かつミリ秒単位の即答性を実現するため、対話内容に応じて推論負荷を階層化しています。

| レイヤー | 対象アクション | LLMトークン消費 | レイテンシ | 処理内容 |
|---|---|---|---|---|
| **Tier 0** | クイックリプライ選択肢タップ | **0 トークン ($0)** | **< 50ms** | LLM意図解釈を介さず、バックエンドの数理CSPソルバーやFirestoreベクトル検索に直結 |
| **Tier 1** | 定型表現（テキスト服登録・天気変更・寒がり調整・Swap） | **0 トークン ($0)** | **< 30ms** | 正規表現・決定論的ルール辞書でミリ秒即答 |
| **Tier 2** | 複雑な自然言語相談・あいまいな質問 | **最小JSON構造化** | **1〜2s** | 会話履歴を全件送信せず「直近1発話＋最小状態要約」のみを Gemini 1.5 Flash に送信 |

### 4.3 プライバシーファースト設計（Zero Raw PII Leakage）

- **Google Calendar API 連携**: Google Identity Services (GIS) による正規OAuth 2.0認可。
- **不可逆サニタイズ**: カレンダー予定の生タイトル・場所・参加者情報はバックエンドのサニタイザーによって「活動分類（office/academic/dining/commute/casual）」「推定代謝量（1.2〜2.6 METs）」「要求フォーマル度（1〜5）」へ不可逆変換されます。
- 個人特定情報（PII）は Vertex AI やログ基盤に一切送信されず、情報漏洩リスクを根本から遮断しています。
- **スマートデモフォールバック**: 審査員が自身のカレンダーを接続しない場合でも、1クリックで多拠点TPO予定を再現できる安全なデモモードを完備。

## 5. 技術スタックと選定理由（Why Google）

| コンポーネント | 採用技術 | 選定理由（Own the Why） |
|---|---|---|
| **フロントエンド実行基盤** | **Firebase App Hosting** | 大会指定の必須実行基盤。Next.js 15 App Router のSSR・最適化ビルドをゼロコンフィグで本番配信可能 |
| **バックエンド実行基盤** | **Google Cloud Run** | Python 3.12 (FastAPI) の高速コンテナ基盤。IAM サービスアカウントによるキーレス認証（ADC）を標準提供 |
| **マルチモーダルAI** | **Vertex AI Gemini 1.5 Flash** | Structured Outputs による型安全なJSON出力。東京リージョン低遅延通信と大会クレジットの有効活用 |
| **画像特徴量抽出** | **Vertex AI Multimodal Embeddings** | `multimodalembedding@001` による1408次元潜在空間への射影。自然言語クエリと衣服画像の特徴類似度を直接計算 |
| **データベース・ベクトル検索** | **Cloud Firestore** | 外部ベクトルDB（Pinecone等）を増やさず、単一のGCPマネージドDB内でドキュメント永続化とネイティブVector Searchを完結 |
| **カレンダー連携** | **Google Calendar API v3** | ユーザーの日常スケジュールを追加入力なしでTPO・METsに変換 |
| **気象データ** | **Google Maps Platform Weather API / Open-Meteo** | 朝・昼・夜の時間帯別気温・降水量・風速を取得し、Clo値計算に直結 |
| **シークレット管理** | **Google Secret Manager** | OAuth Client Secret等の機密情報を安全に注入し、ソースコードや環境変数への平文コミットを防止 |
| **可観測性** | **Google Cloud Logging** | 推薦パイプラインの各ステージ通過数、Clo値、推論レイテンシを構造化ログとして記録 |
