# DevFest GDG Japan Hackathon 2026 開発前提知識・要件定義書

## 1. 大会テーマとコアバリュー
* **テーマ**: 「Own the Why, Build with Intent.」
* **開発方針**: AIエージェントによるコード自動生成時代において、AIの提案を鵜呑みにせず、人間が主導権を握って技術のPros/Consを比較検討することが求められる。技術選定の理由を自らの言葉で語り、明確な意図を持ってプロダクトを構築すること。

## 2. プロダクト要件と制約事項
* **対象カテゴリー（必須）**: 以下の5つから選択。これ以外は審査対象外。
  1. 医療・福祉
  2. 観光
  3. 教育
  4. エンターテインメント
  5. クリエイティブ
* **実行基盤（必須）**: アプリの実行に以下のうち1つ以上を必ず使用すること。
  * App Engine
  * Compute Engine
  * GKE
  * Cloud Run
  * Firebase App Hosting
  * Firebase Hosting
* **AI・他社ツールの利用**:
  * AIコーディング支援ツールの利用は許可されている。
  * プロダクト内部での他社LLM APIの利用は禁止されていないが、「Google技術の活用」の評価観点からGoogleのLLM APIの使用が推奨される。
* **事前開発の禁止**: 11月5日10:00の開発開始以前のソースコード記述は禁止。ただし、UIデザイン、環境構築、技術検証（POC）は許可される（POCコードの商用リポジトリへの直接コピーは不可）。

## 3. 審査基準（合計24点満点）
以下の4領域・計8項目について、それぞれ0〜3点の4段階で評価される。
* **Google技術の活用**
  * Google技術がプロダクトの中核で有効に機能しているか。
  * 目的や要件に対し、Google技術を採用した理由が合理的かつ具体的に説明されているか。
* **プロダクトの完成度**
  * 課題解決に必要な操作が一連の流れとして動くか。
  * 対象ユーザーが目的を達成できるUI・UXになっているか。
  * 安全性・拡張性・保守性を見据えた設計を意識しているか。
* **社会課題への解決力**
  * 解決する課題が具体的かつ明確に示されているか。
  * プロダクトの機能や仕組みが、実際の課題解決に有効であるか。
* **ピッチの構成と説明力**
  * デモ・話の構成が分かりやすくインパクトがあるか。
* **採点外項目（必須記入）**
  * AIをどの場面でどう使ったか、なぜその場面か。
  * 開発を通して何を得て、どれだけ成長したか。
